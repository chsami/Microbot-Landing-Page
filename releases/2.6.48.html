When a script goes wrong and you send a bug report, it can now show us what the script did in the minutes before, not only where you stood when you opened the report. A new Recent activity section adds up to the last 20 minutes of your movement, clicks, game messages and script status, and it stays on your computer until you send a report. Set Target on the world map or in the game view now moves to the nearest walkable tile, so clicking a rock or a deposit box still gives you a route. On the Hub, Varrock Anvil only stops when your bank is really out of bars, Auto Woodcutting banks your logs again in progressive mode, Moons of Peril eats and drinks through the main fight, and Tutorial Island cooks its bread on the range again. This release ships Microbot client 2.6.48 together with those Hub updates.

Bug reports show what led up to the problem

You open a bug report the same way as before: click the red bug button in the sidebar and choose Report a problem..., click the grey bug in a plugin's settings header, or right-click the plugin's name. Until now a report held a snapshot of the game at the moment you opened it, plus the end of the client log. Most Hub scripts write very little to the log while they run. A Giants' Foundry report, for example, said "Not animating" twice and nothing else, so we had to come back and ask you what the script had been doing.

The Report a problem window now has a Recent activity (movement, clicks, game messages) box under Game state. It's ticked by default, and you can untick it for any report you'd rather send without it. With it ticked, the report shows the minutes before you opened it: the script filled the crucible, the bars left your inventory, then the script printed the same error 37 times in a row. That is usually enough for us to find the problem without asking you to make it happen again.

The activity has one short line for each game tick where something changed. Here are a few lines from a Giants' Foundry run:

812 08:13:02.4 p=3361,11500,0 a=899
812 08:13:02.9 click=Fill>Crucible(44776,GAME_OBJECT_FIRST_OPTION)
813 08:13:03.0 inv -2361*14 v13934=14
840 08:13:19.2 out="Cannot invoke "Stage.getHeat()" because the return value is null"
840 08:13:19.3 (previous line repeated 37 more times)

Hover over the box in the window to see the full list. It records:

  • where you walked, your animation, what you attacked, and your HP, prayer and run energy
  • items you gained or lost, written as item numbers
  • game messages, the options you clicked, windows opened and closed, and game settings that changed
  • the script's status, scripts starting and stopping, and anything the script printed
  • a line starting with ! when a script has run for 50 ticks, about 30 seconds, with nothing changing in the game, unless the script is paused or you are using the mouse or keyboard yourself
What stays private

The activity is kept in memory on your computer, 20 minutes at most, and only leaves it inside a report you send. Other players you click or attack show up as "player", and other players' chat isn't recorded. Your own name is removed, as in the other sections. Anything a script prints is included as the script printed it. If you untick Recent log and errors, the script's error output is left out of the activity too.

See what's sent shows the last 40 lines of activity with a short key to the shorthand. Copy report, for pasting into Discord, keeps the last 15 lines. Both always use the latest data, so a preview you open just before sending matches what goes out. Keeping the record costs very little: about half a megabyte of memory and a couple of microseconds per game tick.

Set Target lands on walkable ground

2.6.47 made Set Target on a dungeon map take you into that dungeon. The tile you click still has to be one you can stand on, though. Say you open the world map, switch to the Dwarven Mine map and right-click the deposit box in the Motherlode Mine. The box sits on its own tile, which you can't stand on, and the walker was handed that tile as its target anyway.

Now Set Target and Set Start move to the nearest walkable tile within 16 tiles of the spot you clicked. This works on the world map and with Shift + right-click in the game view. Click the Motherlode deposit box and the target lands on the floor right next to it.

  • If the target moves more than 2 tiles, a game message tells you: "Web Walker: Target moved 5 tiles to the nearest walkable spot."
  • If there's no walkable ground within 16 tiles, you see "Web Walker: No walkable ground near that spot. Pick a tile closer to a path or floor." Your current route stays as it was.
  • If the world map can't match a dungeon to its real tiles yet, you see "Web Walker: Can't set a target in this dungeon from the world map." Close the map and Shift + right-click a tile in the game view instead. In 2.6.47 nothing happened at all in that case.

Plugin updates

Varrock Anvil1.0.4

One player smithing rune 2h swords at the anvil west of Varrock had the script stop with "Could not find bars in bank" while standing at the bank with a hammer and 27 Runite bars in their inventory. The script checked the bank before it had finished loading, and gave up after 3.5 seconds when a withdraw was slow. Now it waits for the bank to load, showing "Waiting for the bank to load", and retries a slow withdraw. The overlay shows "Withdraw failed, retrying (1/3)", and the script only stops after three failed tries in a row. It sets the bank to withdraw items rather than notes, and the stop message names your bar, for example "Out of Runite bars in the bank. Stopping."

Auto Woodcutting1.8.9

With Progressive mode on and banking as the action, your character filled the inventory and set off for the bank. If the bank didn't open on the first try, it turned around and walked back to the trees with a full inventory of logs. Now the script only walks to the progressive tree spot while it is cutting, so it keeps trying the bank until your logs are deposited. If you level up while banking, it heads to the new tree on its next trip. With Firemake only set, progressive mode no longer walks you to a tree spot.

Moons of Peril1.0.7

Players reported that the script never ate or drank prayer potions during the boss fights, and died almost straight away. The main attack phase of the Blood, Blue and Eclipse moons, which is the longest part of each fight, left eating to the QoL plugin. If you hadn't set QoL up, your HP and prayer ran out. Now the script eats and drinks there at your Health % topup and Prayer % topup settings. It still doesn't top up during the Blood Moon jaguar phase, and only tops up at the start of the Eclipse clone phase, so keeping QoL as a backup is a good idea. The setting tooltips say this too.

Tutorial Island1.3.18

At the Master Chef, the script used the wrong option on the range, so your bread dough was never baked. It now picks Cook on the range and bakes your bread. It also answers "No, I'm not planning to do that." when the Magic Instructor offers that choice.

Other fixes

  • In Quest Helper, ticking or unticking the shortest path option in the settings threw an error, and the path to your next quest step was never drawn. It now draws or clears the path as soon as you change the option.
  • A script that switches tabs on the login screen, during a loading screen or during a world hop filled the log with errors. One report had 53 of them. Switching tabs while logged out now just does nothing and tells the script it didn't work, so the script can try again once you are logged in.
  • Scripts that check how far your weapon can reach, such as Zulrah Slayer, hit an error 72 times in a single report when the game couldn't tell them your attack style. They now get your weapon's normal reach instead, for example 7 tiles for a shortbow.
  • If you deploy scripts to the client through the Agent Server, a folder path with a character your system doesn't allow now gets a clear "Invalid sourcePath" reply instead of an internal server error.

For script developers

  • Script.trace(key, value) adds a value to the bug report activity, recorded only when it changes. For example trace("stage", stage) in your loop shows every stage change in the next report. Anything your script prints with System.out or System.err is recorded too; repeats are folded and stack traces are cut to two frames.
  • Rs2Tab.switchTo returns false right away when you're not logged in. Before, it could return true from the cached tab after an error.
  • Rs2Combat.getWeaponAttackStyle can return null when a style lookup fails. getAttackRange() then falls back to the weapon's default range.
  • POST /scripts/deploy on the Agent Server replies 400 with Invalid sourcePath: <reason> when the path can't be parsed.
  • Quest Helper's shortest path toggle runs on the client thread.
  • Main was merged back into development after 2.6.47.

How to update

Restart Microbot to get client 2.6.48. Varrock Anvil 1.0.4, Auto Woodcutting 1.8.9, Moons of Peril 1.0.7 and Tutorial Island 1.3.18 show up in the Microbot Hub panel inside the client.
