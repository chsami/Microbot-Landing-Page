Right-click the world map inside a dungeon, pick Set Target, and the walker now takes you into that dungeon instead of to some spot on the surface. If you start Microbot through the RuneLite launcher with a Jagex Account, Auto Login and the Break Handler log you back in as your character again, instead of typing "default" into the username box. On the Hub, Slayer stops straight away and names a master you can use when the one you picked won't give you a task. Four scripts no longer show errors during loading screens and world hops, and Gem Crab Killer's potion setting fits the panel again. This release ships Microbot client 2.6.47 together with those Hub updates.

Set Target works inside dungeons

The game's world map doesn't draw caves and dungeons where they really are. It draws them in a free part of the map, usually next to the area above them. Say you open the world map, switch to the Dwarven Mine map, right-click inside the Motherlode Mine and pick Set Target. The walker took the spot where the mine happens to be drawn, which is a real tile out near Draynor, and set off with a teleport to get there.

Now Set Target turns the spot you clicked into the tile it stands for, so the walker takes you into the Motherlode Mine. The Target pin shows up on the dungeon map right where you clicked. Set Start works the same way. Targets on the surface behave exactly as before.

2.6.46

Set Target inside a dungeon sent you to wherever that part of the map is drawn, often a different town altogether.

2.6.47

The walker heads into the dungeon you clicked, and the pin sits on the dungeon map where you put it.

Good to know

On a dungeon map the path line is still drawn at the real coordinates, so it doesn't lead to the pin yet. The pin can also show up on another underground map that is drawn over the same spot. If a spot you click on a dungeon map can't be matched to a real tile, no pin appears and your character stays where it is.

Jagex Account auto login works again

Many players start Microbot through the RuneLite launcher with a Jagex Account, set up the way our !jagexaccount guide on Discord explains. Since 2.6.45, Auto Login, the Break Handler and script relogs on that setup typed the profile name, usually "default", into the username box instead of logging in as your character. Logging in by hand still worked, so you only noticed after a break or a disconnect, when the client sat on the login screen.

Now a profile without a saved password logs in with the Jagex character the client was started with. Say you start your character "IronMiner42" on the "default" profile and the Break Handler takes a 20-minute break. When the break ends, IronMiner42 is logged back in and your script carries on.

  • A profile with a saved username and password still logs in with those, as in 2.6.45.
  • The client reads your launcher login once, when it starts. If you then start a second client for another character, the first client keeps logging in as its own character.
  • The launcher login is only used when it belongs to the character this client was started with, so a client never logs you in as a different character.

2.6.46 fixed the same problem for Play With Jagex Account in the Microbot launcher. This release fixes it for the RuneLite launcher.

Slayer tells you when a master is out of reach

The Slayer plugin uses Duradel by default, and Duradel only gives tasks from 100 combat and 50 Slayer. One player with 63 combat and 12 Slayer started the plugin without changing that setting. It walked them all the way to Shilo Village and then stood there on "getting task", because Duradel never gives that account a task.

Now Slayer 1.1.7 checks your combat and Slayer levels before it walks to your master to get, skip or block a task. If they're too low, it stops before walking anywhere and tells you what to pick instead:

Slayer stopped

Duradel only gives tasks from combat level 100; you are combat level 63. Vannaka works at your level with no quest needed. Pick a Slayer Master you can use in the plugin settings, then start the plugin again.

  • From 85 combat it suggests Nieve, or Steve once you've finished Monkey Madness II.
  • Below that it also names a master that needs a quest when one fits your level, such as Chaeldar after Lost City.
  • Hover over the Slayer Master setting to see what each master needs, one per line.
  • If you already have a task, the check doesn't stop you.

The plugin doesn't check quests yet. With 100 combat and 50 Slayer it still walks you to Duradel, even if you haven't finished Shilo Village.

Plugin updates

A loading screen, a world hop or a teleport leaves the game without your position for a moment. Four scripts tripped over that moment and filled the log with errors. They now wait for the next tick and carry on.

Auto Essence Mining1.0.6

When Aubury teleports you to the essence mine, or you take the portal back to Varrock, the script showed a red error with a stack trace ten times a second until you arrived. It looked as if the script had crashed, even though it picked up again afterwards. Now it waits quietly until your position is back.

Mahogany Homes0.0.18

If your position went missing just as the script checked whether you were inside a client's home, the loop failed with "Mahogany Homes script loop failed". Now it counts that moment as being outside every home and checks again on the next tick.

MicroAgility1.3.3

On the Agility Pyramid, after you hand your pyramid tops to Simon, the script walks back to the start of the course. If your position went missing right then, it logged an error. Now it skips that walk-back and heads to the start on the next tick, as it would have anyway.

AutoHunter1.5.6

While catching chinchompas, a world hop or loading screen could stop the tick with an error as the script moved to a new trap spot. Now it skips that tick and tries again a quarter of a second later.

Gem Crab Killer1.0.6

The Offensive potion option added in 1.0.5 was cut off to "Offensiv..." in the plugin panel. It's now called Potion, and your saved choice stays as it was.

Other fixes

  • Scripts that type a price into a Grand Exchange offer, or press the -5% and +5% buttons, read the price box wrongly in some game sessions. They typed the price again every time with an error in the log, and a +5% click could move on too early or time out. The price is now read correctly in every session.
  • Scripts can show a short pop-up message over the game view. It only worked in the resizable classic layout. In fixed mode or the resizable modern layout it failed with a "component does not exist" error. It now opens in whichever layout you play in. On the login screen or during a loading screen the pop-up is skipped instead of causing an error.

For script developers

  • Microbot.openPopUp opens on the notifications layer of the active toplevel: fixed (548), resizable classic (161) or resizable modern (164). It returns without opening anything when you're not logged in or another toplevel is active. If players must see the text, also send it as a game chat message.
  • Rs2GrandExchange.getOfferPrice() reads varp 5753 as a long and falls back to the int value when the game stores it as an int. Read it the same way if your script reads that varp itself.
  • ShortestPath 1.0.6: world map Set Target, Set Start and Set Test turn the clicked map point into the real tile with WorldPointMapper, limited to the map being viewed. ShortestPathPlugin.createTargetMarker builds every Target pin at the map position of the real tile, and Rs2PathApi.createTargetMarker uses it too. Pathing still uses the real tile.
  • JagexCredentials.fromLaunch() reads the launch credentials once per client, so a credentials file rewritten by a later launch doesn't change this client's character.

How to update

Restart Microbot to get client 2.6.47. Slayer 1.1.7, Auto Essence Mining 1.0.6, Mahogany Homes 0.0.18, MicroAgility 1.3.3, AutoHunter 1.5.6 and Gem Crab Killer 1.0.6 show up in the Microbot Hub panel inside the client.
