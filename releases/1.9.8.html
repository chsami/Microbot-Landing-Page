The Microbot Hub is a separate repository built for community plugins and scripts. Think of it as the Grand Exchange for Microbot plugins: one place where developers share, discover and work on automation together, while the core client stays small and stable.

Why the Hub exists

Every plugin that lived inside the main client made it bigger, slower to build and harder to keep stable. The Hub moves community plugins out of the client so both can move at their own pace.

  • A lean main client. The core keeps only essential, battle-tested features, which means faster start-up, lower memory use and fewer crashes.
  • Faster plugin updates. Developers can ship a plugin fix without waiting for the next client release.
  • Clear quality lines. Experimental and community plugins live apart from production-ready core features.
  • Room to grow. The plugin list can keep growing without making the client heavier for everyone.

Contributing a plugin

1. Fork and branch

git clone https://github.com/YourUsername/microbot-hub.git
cd microbot-hub
git checkout -b feature/your-plugin-name

Use fix/issue-description for bug fixes.

2. Keep changes focused

One plugin or one feature per pull request. Large pull requests that touch several plugins are hard to review and slow to merge.

3. Test thoroughly

  • Run the plugin in the situations players will actually use it in.
  • Check edge cases, such as a full inventory, death, or a world hop mid-task.
  • Watch for memory leaks on long sessions.
  • Make sure it still works alongside other popular plugins.

4. Open a pull request

git add .
git commit -m "Add: new plugin for XYZ"
git push origin feature/your-plugin-name
Pull request checklist
  • Code follows the project style.
  • The plugin has been tested in game.
  • Documentation is complete and accurate.
  • No hard-coded values or magic numbers.
  • Errors are handled instead of crashing the script.
  • Screenshots or GIFs are included where they help.

Troubleshooting

"Unsupported class file major version"

Gradle is running on the wrong Java version. Point it at JDK 11:

java -version
export JAVA_HOME=/path/to/java11
./gradlew -version

A plugin fails to load because of missing dependencies

  • Check dependencies.txt in the plugin folder.
  • Refresh them with ./gradlew build --refresh-dependencies.
  • Make sure any plugins it depends on are enabled.

The build fails with compilation errors

./gradlew clean
./gradlew build --refresh-dependencies
./gradlew compileJava --info

Design principles

Keep the main client lean

Only essential features belong in the core. That keeps start-up fast, memory low and the client easy to maintain.

Make iteration quick

Hub developers can ship updates straight away, try new ideas and act on player feedback quickly.

Keep setup simple

Cloning and building the Hub should take one command, need almost no configuration and be friendly to first-time contributors.

Get started

Ready to build something? Visit the Microbot Hub repository, browse the plugins already there, or come and talk it through on Discord.
